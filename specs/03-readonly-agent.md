# F03 · 能搜索并阅读仓库的 Agent

## 目标与用户结果

用户给出代码问题，Agent 自主搜索、读取文件，并在回答中指出文件位置。

受影响用户：本地使用扣仔的开发者及嵌入方。依赖：F02。当前状态见 [实施状态](status.json)，本文不重复维护状态。

## 范围与非目标

范围：消息/工具契约、工具注册与参数校验、list/read/search、最小执行循环、run 子命令、轮数上限。

非目标：没有文件写入或 shell；不把代码及工具输出中的指令提升为系统指令。

## 主流程

用户输入 → 模型返回完整调用 → 统一执行器校验 → 搜索/读取 → 结构化结果回传 → 下一轮回答。

## 错误与边界

未知工具、参数非法、文件缺失、越界路径、二进制内容及输出截断均提供明确结果；空结果不伪造命中。

## 数据、接口与安全约束

ToolCall/ToolResult 以稳定 call_id 关联；工具状态包含 ok/error/cancelled/unknown。read 返回路径与行范围；search 返回命中行和截断标记。拒绝根目录外及符号链接逃逸。

## 验收条件

- F03-AC1：固定模型按 search→read→回答执行；测试断言最终回答依据实际文件内容及行号。
- F03-AC2：未接收完整参数前工具执行次数为零。
- F03-AC3：工具失败可以作为结果交给模型继续处理，不导致无界循环。
- F03-AC4：路径 ../ 和指向工作区外的符号链接均被拒绝。
- F03-AC5：达到轮数上限时以预算耗尽结束，返回非零，JSON 有明确终止原因。

验收按每条前置条件建立测试夹具，触发所述事件并断言实际输出、状态及副作用；仅“没有抛异常”不足以通过。正常路径和错误路径至少各有一条集成测试，外部服务另用显式 smoke。
