# KOTTO 首版：十个功能点

用户约定：最多十个功能点，每个功能点完成后提交并推送 GitHub 一次，最后一个功能点结束时首版功能完整。项目路径之外的上层目录用于 harness 资料，不作为源码仓库。

## 首版完整的定义

一个本地 Python Agent Harness，可通过 CLI 或 Python 接口调用一家经过验证的模型服务，在明确授权的执行环境中搜索/读取/编辑代码、执行测试；具有流式输出、取消与补充要求、资源预算、会话记录与恢复、项目规则与上下文压缩、可信扩展与 Skill。覆盖 macOS/Linux；不承诺未经验证的 Windows 或全部兼容服务。

仅有离线夹具或模拟模型不等于真实模型验证。F10 必须实际跑通安装和真实代码任务；缺少凭据时保持 NOT_READY，不把跳过视作通过。Web UI、多 Agent、长期记忆、插件市场、云部署不在首版。

## 提交规则

- 恰好规划十个功能提交，F01 包含原有骨架与全部规格，不额外创建“初始化”“只写文档”等占位功能提交。
- 每项在本地完成测试驱动实现、回归与审查后一次提交并推送。F10 集成修复在最后一次功能提交前完成。
- 未实现的功能不提交虚假的 DONE 状态；不强制推送或改写公开历史来凑次数。
- 代码、测试和实施文档可公开；真实凭据、会话、用户代码附件和上层资料目录不加入 Git。
- 用户已授权逐项提交 GitHub；模型凭据仍由用户配置，代码使用 MIT，品牌素材不随代码许可自动授权。

## 已确认决策

- 单包 src 布局、Python 3.11+、CLI 优先，沿用现有设计。
- 首个服务已确定为 DeepSeek，使用官方 OpenAI 兼容接口；默认模型 deepseek-flash 可配置。F01 不联网，真实调用在 F02 验收。
- 用户已确定代码 MIT，扣仔品牌素材单独约定，参见 ../BRAND.md。
- GitHub 仓库已创建为 jimmyfenwick/kotto；每项推送后核对远端 HEAD，提交记录以 Git 历史为准。

## 推进方式

从 F01 开始，按依赖顺序逐项实施。每次回报已完成的功能编号、实际验证结果和远端提交链接。功能跨会话时从状态与已有代码继续，不重建计划，不擅自扩大范围。
