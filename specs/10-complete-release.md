# F10 · 完整集成、发布包与最终验收

## 目标与用户结果

新用户可按 README 安装配置，完成真实代码任务、恢复会话并使用扩展；全部约定能力有证据。

受影响用户：本地使用扣仔的开发者及嵌入方。依赖：F01–F09 全部完成。当前状态见 [实施状态](status.json)，本文不重复维护状态。

## 范围与非目标

范围：真实任务回归集、完整安装和端到端验证、文档收口、兼容性说明、CI、本地构建、功能矩阵、就绪结论。

非目标：不发布 PyPI、不部署生产、不做网站；无真实服务证据时不宣称功能完整或 READY。

## 主流程

新环境安装 → 配置真实模型 → 阅读仓库 → 修复 bug → 运行现有测试 → 查看并恢复会话 → 扩展调用 → 验收记录。

## 错误与边界

任一关键规格失败、缺真实模型验证、安装失败、泄漏凭据或遗留子进程均使最终状态 NOT_READY；保持修复在本功能点提交前完成。

## 数据、接口与安全约束

锁定文档中的支持平台和模型协议；CLI help、示例、包版本与行为一致。CI 使用无密钥夹具；真实 smoke 单独启用，不把 SKIP 算 PASS。使用用户已确认的代码 MIT 许可与独立品牌约定。

## 验收条件

- F10-AC1：干净临时环境能构建 wheel/sdist 并安装，命令与 Python 嵌入示例均可运行。
- F10-AC2：固定基线的阅读、修复 bug、小功能三类任务以实际检查验收，不只评判模型回答。
- F10-AC3：至少一次指定真实模型完成工具调用和改码验证；记录服务、模型、时间及结果，不记录 Key。
- F10-AC4：全量离线测试和本地 CI 等价检查通过；推送后检查 GitHub CI 结果。
- F10-AC5：回查 F01–F09 全部验收条款，未验证或失败为零后才标记完整可用；记录宿主执行与概念外的限制。

验收按每条前置条件建立测试夹具，触发所述事件并断言实际输出、状态及副作用；仅“没有抛异常”不足以通过。正常路径和错误路径至少各有一条集成测试，外部服务另用显式 smoke。

## 实施与验证

预期影响：evals/、tests/integration/、examples/、README.md、docs/、pyproject.toml、.github/workflows/。

计划验证命令（对应测试须在本功能点实现时新增，当前未执行）：

```text
PYTHONPATH=src python3 -m unittest discover -s tests -v；构建安装、真实 smoke 与任务验收命令在具体实现后补全并实际执行
```

测试驱动：先运行因缺失能力而失败的聚焦验收，再实现并通过；提交前运行全量回归及必要打包检查。

## 提交边界

一个功能点完成一次提交，提交信息：

```text
feat(F10): complete integrated harness and release verification
```

本次提交需包含实现、测试、必要文档及状态证据；推送后核验远端 HEAD 等于本地提交。未通过验收不提前标记 DONE，不用仅写规格的提交冒充功能完成。修复在提交前合并到同一切片；如已推送后发现缺陷，先报告对提交次数的影响，不改写公开历史。

## 风险、假设与开放项

禁止通过减少原验收范围、伪造真实服务结果或把未完成项移出首版来满足最后一步。

负责人：当前开发协作，由用户裁定模型服务、许可及改变首版范围的取舍。事实来源：用户本次最多十个功能点、每项提交 GitHub 的要求，以及 [项目架构](../docs/architecture.md)。设计中的协议与平台支持在实现时核验，本文不代替真实兼容性证据。
