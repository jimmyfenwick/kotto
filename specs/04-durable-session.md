# F04 · 会话记录、附件与安全恢复基础

## 目标与用户结果

用户能查看和恢复任务历史，并能识别中断后工具执行状态是否确定。

受影响用户：本地使用扣仔的开发者及嵌入方。依赖：F03。当前状态见 [实施状态](status.json)，本文不重复维护状态。

## 范围与非目标

范围：版本化追加日志、单写入者锁、会话列表/查看/继续、受控附件存储、损坏尾行处理、不确定调用识别。

非目标：不声称任意外部副作用恰好执行一次；恢复历史不自动重放工具。

## 主流程

获取会话锁 → 记录输入与完整模型消息 → 工具执行前落意图 → 执行后落结果 → 关闭释放锁；恢复时先检查日志。

## 错误与边界

重复打开、版本不支持、日志中间损坏、写盘失败要显式失败。仅尾部不完整记录可受控恢复；不能默默跳过中间损坏。

## 数据、接口与安全约束

session_id/run_id/tool_call_id 稳定关联；事件有版本和序号。执行前持久化意图失败时不允许工具继续。没有结果的执行保留 unknown 并要求核验。附件 ID 不能逃逸根目录。

## 验收条件

- F04-AC1：进程结束后重新打开会话能重建消息与工具结果。
- F04-AC2：第二写入者被锁拒绝；进程崩溃后有明确锁恢复机制。
- F04-AC3：模拟执行后结果保存前崩溃，恢复后标记 unknown，外部执行计数不增加。
- F04-AC4：截断尾行可报告并修复，中间 JSON 损坏则拒绝继续。
- F04-AC5：大结果返回截断摘要及可读附件引用，凭据不作为事件写盘。

验收按每条前置条件建立测试夹具，触发所述事件并断言实际输出、状态及副作用；仅“没有抛异常”不足以通过。正常路径和错误路径至少各有一条集成测试，外部服务另用显式 smoke。

## 提交边界

一个功能点完成一次提交，提交信息：

```text
feat(F04): persist sessions and detect uncertain tool executions
```

本次提交需包含实现、测试、必要文档及状态证据；推送后核验远端 HEAD 等于本地提交。未通过验收不提前标记 DONE，不用仅写规格的提交冒充功能完成。修复在提交前合并到同一切片；如已推送后发现缺陷，先报告对提交次数的影响，不改写公开历史。

## 风险、假设与开放项

日志可能包含代码和路径；默认存储位置、保留与删除方式须说明，日志不会随源码推送。
