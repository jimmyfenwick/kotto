# F07 · 取消、补充要求与资源预算

## 目标与用户结果

长任务中用户能中断、补充要求，并了解为何结束及使用了多少资源。

受影响用户：本地使用扣仔的开发者及嵌入方。依赖：F06。当前状态见 [实施状态](status.json)，本文不重复维护状态。

## 范围与非目标

范围：单实例并发保护、取消传递、steer 队列、总超时、模型轮数与工具调用上限、可用 token 用量累计、结构化状态。

非目标：价格未知时不伪造费用；不支持多 Agent 并行调度。

## 主流程

运行期间接收输入 → 补充要求排队在下一轮生效，或取消当前模型/工具 → 清理 → 记录终止原因。

## 错误与边界

消费方不再读取事件时须关闭运行并清理；重复取消幂等；正在执行的工具不因 steer 重复开始。

## 数据、接口与安全约束

Agent.run/steer/cancel；输入队列有顺序；run_end 具有 completed/cancelled/failed/budget_exhausted 原因。第二 run 明确拒绝，不共享活动状态。

## 验收条件

- F07-AC1：取消慢模型与慢 shell 均能在限定测试时间内结束，不留下子进程。
- F07-AC2：流式消费者提前关闭后清理执行，保持会话状态可恢复。
- F07-AC3：两条 steer 消息按顺序在下一轮模型输入出现，不重跑前一工具。
- F07-AC4：轮数/调用数/总时间预算各自触发正确终止原因。
- F07-AC5：同一 Agent 并发 run 被拒绝，结束后可以启动新 run。

验收按每条前置条件建立测试夹具，触发所述事件并断言实际输出、状态及副作用；仅“没有抛异常”不足以通过。正常路径和错误路径至少各有一条集成测试，外部服务另用显式 smoke。
