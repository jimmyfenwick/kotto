# F02 · 真实模型流式对话

## 目标与用户结果

用户配置模型后能发起一次真实对话，并看到流式文本与明确错误。

受影响用户：本地使用扣仔的开发者及嵌入方。依赖：F01。当前状态见 [实施状态](status.json)，本文不重复维护状态。

## 范围与非目标

范围：DeepSeek 官方 OpenAI 兼容 HTTP 接口、供应商适配、chat 子命令、流式解析、用量及结束原因、配置示例。

非目标：不宣称兼容所有供应商；第一版只保证文档中验证过的协议子集，暂不执行工具。

## 主流程

解析配置 → 构造请求 → 读取流式响应 → 输出文本增量 → 记录终止原因与可用用量。

## 错误与边界

401、429、5xx、连接失败、流中断、畸形事件、缺少终止标记分别明确失败；已输出的半段内容不得提交为完整模型消息。自动重试不得重复完整回答。

## 数据、接口与安全约束

ModelGateway 接收消息与工具定义，产出带类型的 ModelEvent；供应商扩展字段和必要元数据有明确保留路径。Key 仅进入认证请求头。chat 支持结构化 JSON 输出。

## 验收条件

- F02-AC1：本地 HTTP 夹具逐段发送数据时，CLI 在响应结束前输出首段文本。
- F02-AC2：多段 UTF-8、跨数据块事件、用量缺省均能正确处理。
- F02-AC3：认证失败输出可理解原因，不泄露 Key；异常响应正文不无条件回显。
- F02-AC4：服务端中途断开时返回非零，保留输出为未完成状态。
- F02-AC5：使用用户指定的真实服务执行一次低成本 smoke；无凭据时只记录未验证，不能将夹具通过冒充真实成功。

验收按每条前置条件建立测试夹具，触发所述事件并断言实际输出、状态及副作用；仅“没有抛异常”不足以通过。正常路径和错误路径至少各有一条集成测试，外部服务另用显式 smoke。

## 提交边界

一个功能点完成一次提交，提交信息：

```text

```

本次提交需包含实现、测试、必要文档及状态证据；推送后核验远端 HEAD 等于本地提交。未通过验收不提前标记 DONE，不用仅写规格的提交冒充功能完成。修复在提交前合并到同一切片；如已推送后发现缺陷，先报告对提交次数的影响，不改写公开历史。
