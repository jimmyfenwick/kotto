# F09 · 可信扩展、Skill 与嵌入接口

## 目标与用户结果

开发者能添加一个工具或任务指引，并从 Python 程序运行同一个 Agent 核心。

受影响用户：本地使用扣仔的开发者及嵌入方。依赖：F08。当前状态见 [实施状态](status.json)，本文不重复维护状态。

## 范围与非目标

范围：显式配置的可信 Python 插件、工具注册、命令/事件订阅、Skill 文档加载、冲突检测、真实示例、公共 SDK 导出。

非目标：不做插件市场、任意代码隔离、热更新或自动下载执行第三方插件。

## 主流程

用户显式指定扩展 → 加载并注册 → 校验命名冲突 → 运行 Agent → 扩展工具经过统一权限与记录入口。

## 错误与边界

加载异常、重复工具名、订阅器错误、无效 Skill 路径均明确报告；监听器故障不能悄悄吞掉核心运行状态。

## 数据、接口与安全约束

ExtensionHost 公开注册及订阅接口，不能直接修改内部状态。Skill 是文本指引，不等于 Python 插件；可信插件具有宿主进程权限。SDK 对外支持 run/steer/cancel 与结构化事件。

## 验收条件

- F09-AC1：样例扩展提供一个真实工具，模型调用它后产生可验证结果。
- F09-AC2：默认不加载工作区中未经指定的 Python 插件。
- F09-AC3：扩展工具与内置工具遵循相同授权及日志路径。
- F09-AC4：嵌入示例无需 CLI 即可运行并消费事件。
- F09-AC5：重复注册明确拒绝；Skill 加载遵循作用域和上下文预算。

验收按每条前置条件建立测试夹具，触发所述事件并断言实际输出、状态及副作用；仅“没有抛异常”不足以通过。正常路径和错误路径至少各有一条集成测试，外部服务另用显式 smoke。

## 实施与验证

预期影响：extensions/host.py、extensions/manifest.py、extensions/skills.py、src/kotto/__init__.py、examples/。

计划验证命令（对应测试须在本功能点实现时新增，当前未执行）：

```text
PYTHONPATH=src python3 -m unittest discover -s tests -p 'test_extension*.py' -v
```

测试驱动：先运行因缺失能力而失败的聚焦验收，再实现并通过；提交前运行全量回归及必要打包检查。

## 提交边界

一个功能点完成一次提交，提交信息：

```text
feat(F09): expose trusted extensions skills and embedding SDK
```

本次提交需包含实现、测试、必要文档及状态证据；推送后核验远端 HEAD 等于本地提交。未通过验收不提前标记 DONE，不用仅写规格的提交冒充功能完成。修复在提交前合并到同一切片；如已推送后发现缺陷，先报告对提交次数的影响，不改写公开历史。

## 风险、假设与开放项

可信插件不是沙箱内代码，安装和启用属于用户明确选择；不能向用户承诺统一工具权限限制插件任意 Python 行为。

负责人：当前开发协作，由用户裁定模型服务、许可及改变首版范围的取舍。事实来源：用户本次最多十个功能点、每项提交 GitHub 的要求，以及 [项目架构](../docs/architecture.md)。设计中的协议与平台支持在实现时核验，本文不代替真实兼容性证据。
