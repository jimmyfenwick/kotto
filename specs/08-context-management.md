# F08 · 项目规则与长任务上下文管理

## 目标与用户结果

Agent 能应用项目规则，并在历史增长时继续工作而不丢失目标和约束。

受影响用户：本地使用扣仔的开发者及嵌入方。依赖：F07。当前状态见 [实施状态](status.json)，本文不重复维护状态。

## 范围与非目标

范围：系统/项目/用户信息分层、根及子目录规则作用域、上下文预算、工具大输出引用、历史压缩、摘要持久化。

非目标：不做跨会话长期记忆、向量检索或自动全库索引；不保证任意长度目标都能塞进窗口。

## 主流程

计算本轮必需输入 → 加载适用规则 → 预算不足时生成可追溯摘要并保留合法工具对 → 组装请求。

## 错误与边界

必需规则和当前要求超出预算时明确报错；摘要失败保留原历史且不提交坏摘要；预算估计误差和模型超窗需显示。

## 数据、接口与安全约束

原始日志不删；摘要保留用户约束、决策、证据位置、未完成事项。项目根规则全局适用，子目录规则仅对相关路径生效；外部资料不升级优先级。未知 tokenizer 使用明确标记的保守估计。

## 验收条件

- F08-AC1：根与子目录规则按文档作用域生效，相邻目录规则不污染其他路径。
- F08-AC2：压缩前后用户约束和当前目标仍存在，工具调用与结果配对合法。
- F08-AC3：摘要失败或窗口不足时不删除历史、不隐式丢弃规则。
- F08-AC4：含提示注入的工具结果不会改变程序的权限策略。
- F08-AC5：长会话可在测试窗口内继续多轮，原始消息仍可在日志中查看。

验收按每条前置条件建立测试夹具，触发所述事件并断言实际输出、状态及副作用；仅“没有抛异常”不足以通过。正常路径和错误路径至少各有一条集成测试，外部服务另用显式 smoke。

## 实施与验证

预期影响：context/builder.py、context/project_rules.py、context/budget.py、context/compaction.py、session/store.py。

计划验证命令（对应测试须在本功能点实现时新增，当前未执行）：

```text
PYTHONPATH=src python3 -m unittest discover -s tests -p 'test_context*.py' -v
```

测试驱动：先运行因缺失能力而失败的聚焦验收，再实现并通过；提交前运行全量回归及必要打包检查。

## 提交边界

一个功能点完成一次提交，提交信息：

```text
feat(F08): manage scoped rules and compact long contexts
```

本次提交需包含实现、测试、必要文档及状态证据；推送后核验远端 HEAD 等于本地提交。未通过验收不提前标记 DONE，不用仅写规格的提交冒充功能完成。修复在提交前合并到同一切片；如已推送后发现缺陷，先报告对提交次数的影响，不改写公开历史。

## 风险、假设与开放项

模型摘要可能遗漏事实，必须保持原始记录可查，关键不可变约束由程序单独保留。
